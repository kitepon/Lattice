# ADR 0198: ページは記録された端末名を出さず、公開labelか番号で出す

- Status: accepted
- Date: 2026-10-12
- Amends: [ADR 0197](0197-terminal-label-instead-of-os-hostname.md)（公開面へ出す名前の範囲）

## Context

ADR 0197は、これから書く記録の`actor.host`と、hubの公開一覧の「配信元」から、OSのhost名を外した。
同じ日の再確認（SEC-009）で、projectごとのページに残っていると分かった。ページの作業記録の欄は、
各記録の来歴を「記録者 端末名/agent」と出す。その端末名は、記録が書かれた時の`actor.host`そのままである。
過去の記録にはOSのhost名が入っており、ページはhubを通って誰にでも配信される。

記録に残る端末名は自由文である。OSのhost名のことも、席が`LATTICE_TODO_ACTOR_HOST`で自分に付けた名前の
こともある。どちらも持ち主の名前を含みうるし、ページの側からは見分けられない。

過去の記録は書き換えない（journalと作業記録はappend-onlyで、digestの鎖がbytesを固定している）。

## Decision

1. **ページは、記録された端末名をそのまま出さない。** 出してよいのは端末の公開label
   （`terminal-`と16進12桁、ADR 0197）の形の名前だけである。
2. **それ以外の名前は、番号に置き換える。** 同じprojectのページの中で、同じ名前に同じ番号を振り、
   「端末1」「端末2」と出す。OSのhost名も、席が付けた名前も、同じ扱いにする。端末の区別は残る。
   - 番号は、その名前が最初に記録された時刻の順に振る。同時刻は名前の順。記録は追記だけなので、
     後から現れた名前は後ろの番号になり、振った番号は動かない。
   - 名前のhashは使わない（ADR 0197 Decision 2と同じ理由。推測した名前を確かめる手段になる）。
3. **手元のdashboardでも同じ表示にする。** 描画は、その応答が公開面へ中継されるかを知らない。知らせる
   仕組みを足すと、bridgeとdashboardの版がずれた時に、置き換えの無いページが公開面へ出る。常に
   置き換えれば、ずれても出ない。元の名前は記録そのもの（`.lattice/todo/`）で読める。
4. **記録の本体は変えない。** 変えるのは表示だけである。
5. `agent`はそのまま出す。

## Consequences

- projectごとの入口は、ページ（`/projects/<id>/`）と更新の通知（`/projects/<id>/events`）の2つである。
  通知が運ぶのはhead digestとerror codeだけで、記録者の名前を運ばない。記録者の名前が出るのはページの
  作業記録の欄だけで、ここを置き換える。静的な`todo gantt`の出力も同じ描画を通る。
- 作業記録の本文（Markdown）は対象外である。本文に書かれた名前は、書いた者の文章として表示される。
- 番号はprojectごとに振るので、同じ端末がprojectによって別の番号になる。project間で端末を突き合わせる
  用途には、公開label（0.78.0以降の記録）を使う。
- 記録の上限で古い記録がページから省かれると、番号の基準になる「最初の記録」が変わりうる。その時は
  番号が詰まる。表示の区別は保たれる。
