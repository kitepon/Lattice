# 最終成果から逆算するLattice工程作成

- Lattice plan: `backward-feature-authoring-20261023`

## 目標

オーナーが「Latticeで工程作って」と依頼した時、操作AIが最終成果と受入条件から必要な機能を逆向きにたどり、各工程の入力となる機能と、その工程が提供する機能を定義してからLattice工程を作る。工程の担当者は、個別の作業内容に加えて全体の目的、後続が何を必要とするか、未解決の問いを着手時に受け取る。

実装中にオーナーのゴールが変わった時は、新しいゴールから機能と工程を組み直し、進行中のplanを修正できる。既に終わった仕事のうち新しいゴールでも成立するものは保持し、意味が変わった仕事だけを再実行又は退役させる。

## 成功条件

1. 最終成果の受入条件から始め、必要な機能を再帰的に宣言できる。機能は「必要とする機能」「提供元」「その機能の受入条件」を持ち、工程ごとに必要・提供機能が機械可読で残る。
2. 後続が必要とする既知の機能に提供工程が無い、提供工程がその機能を成果に含めていない、必要な工程依存が無い場合は、工程登録前に該当機能と工程を示す。単にToDoの題名やMarkdownの語感が似ていることを証拠にしない。
3. 未知の機能・提供元・仕様は理由と次に解く問いを伴って明示できる。未知を完成済みの機能へ丸めず、未知があるという理由だけでゴールと工程の修正を拒否しない。
4. `todo show`と着手結果から、全体の目的・成果の受入条件、担当工程の必要・提供機能、その機能を必要とする後続工程、未解決事項を追加の文書探索なしで読める。
5. ゴール変更を既存planの後継版として反映できる。工程・依存・機能が増減しても、変更と無関係なtaskの完了証拠を保ち、意味が変わるtaskの状態は明示的に見直す。工程修正そのものを過剰なsource照合や無関係な状態の失効で塞がない。
6. Claude、Codex、Cursorの対応hostでは「Latticeで工程作って」という依頼を受けたAIに正規の逆算入口が示される。Lattice内でAIを二重に起動せず、意味の分解と未知の判断は操作AIが行う。
7. 初回作成とゴール変更の実repo一気通貫を確認し、公開版・導入・利用面で結果を確かめる。

## 逆算する機能関係

最終成果を成立させるために、次の機能が必要である。

| 必要な機能 | そのために必要な機能 | 提供する工程 |
| --- | --- | --- |
| 依頼から工程作成が始まる | AIが逆算の正規入口と契約を知る | AI向け導線 |
| ゴールに沿う工程を登録する | ゴール、機能、提供元、工程の対応が検査できる | 機能契約と初回作成 |
| 担当者が後続の用途を踏まえて遂行する | 全体目的、必要・提供機能、利用者、未知を工程から読める | 作業文脈の配信 |
| ゴール変更後も工程を続けられる | 機能関係の更新、taskの状態移行、後継版 | ゴール変更と再コンパイル |

この表は実装順を定める。機能の出力が別工程の入力になる時、その関係を工程契約に記録する。コードのread/write境界や並列可否は既存のindependence compileが別に扱う。

## 判断

- AIはオーナーのゴールと受入条件を読み、必要な機能を逆向きに分解する。Latticeは宣言の構造的な欠落、参照、循環、工程間の接続を検査して記録する。意味上の十分性を機械が推測しない。
- 各工程に必要・提供機能を定義する。ただし未知を許す。未知は理由と次に確かめる問いを持ち、担当者へ渡す。完全な仕様を先に書けることを作成条件にしない。
- 機能関係はplan versionへ束縛する。ゴール変更は旧版を改変せず、後継版へ再コンパイルする。既存taskの状態移行は意味の変化に基づいて明示する。
- 作成と修正の公開入口は、前提確認、検証、保存、結果の読戻しまで一回で終える。既存の低層schemaや端末ごとの手順をAIへ組み立てさせない。
- 既存の`todo structure`はplan定義後のcode-dataflow検査として維持する。今回の機能契約は、code anchorがまだ決まっていない段階でも使える工程作成の入力である。

## 対象外

- Lattice内部からAIを呼び、機能の意味を生成・採点すること。
- 未知の消滅、意味的十分性の証明、完成前の全実装詳細の要求。
- 既存の全planを推測で新しい機能契約へ移行すること。

工程状態と依存はLattice storeを正本とする。本書は目標、必要な機能、判断、受入条件の正本であり、作業中／完了の状態は`lattice todo status --json`で読む。
